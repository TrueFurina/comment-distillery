第三方依赖
01 · WHY

这条赛道的前两层已经卷完了，第三层几乎没人做深

现有的 L1 采集与 L2 统计摘要都很成熟。但它们都停在「告诉你大家什么情绪」。 真正值钱的问题在后面 —— 而这一跳没人系统性地补。

L1 采集              L2 统计摘要           L3 建设性综合
────────────────    ──────────────────    ─────────────────────────
MediaCrawler 6万★     情感分布 / 词云 /      认知框架 + 共识 vs 争议
BilibiliCrawler       高频主题 / 几句金句    + 反例对冲 + 引用溯源
平台自带导出          …然后就没有然后了      + 行动清单 + 盲区说明
                                            ★ 这里
⚖️

反例对冲

每条共识都必须配反方论据。语料一片和谐时，必须主动去楼中楼与低权重长文里开采反例，不能因为「没看到反例」就省略本章。

  • 实测：《火柴人 VS 数学》一级评论几乎全正向
  • 实质反驳 69 条全在楼中楼
🔗

引用溯源

每条带数据的结论都要标 [源:ID|权重N|层级]，并用脚本与语料全集做差集机验 —— 差集非空就不许交付。

  • 靠这一步在自己产出的指南里 抓到过 2 次幻觉引用
  • 诚实的降级是减少引用条数，不是留一个「看起来对」的 ID
🫥

盲区诚实说明

主动披露四类偏差，并写清「哪些部分没读」。指南的附录不是装饰，是可信度的一部分。

  • 幸存者偏差 / 平台偏差
  • 算法偏差 / 时间偏差
它不是爬虫、情感饼图、词云、舆情仪表盘。它是一个把群体文本转成认知结构的 Skill —— 「把一堆七嘴八舌，炼成一份能照着做、且知道哪里可能错的东西」。
02 · PIPELINE

六步流水线 · 全部可机验

前三步是工程，后三步是判断。每一步的产物都落盘，任何一条结论都能倒推回具体条目。

1
接入Ingest
任意平台的导出 CSV，或直接用桌面工具的「采集」页拉 B 站评论（含楼中楼）。字段别名自动识别，编码容错 utf-8-sig → gb18030 → gbk。
▼
2
预处理Prep
按 ID 去重 → 去噪 → 按权重降序 → 产出规范语料 corpus_ccf.csv、易读文本 all_comments.txt、真信号区 low_score_long.txt、统计与 ID 溯源映射。先看 dup_dropped，再信任何规模数字。
▼
3
通读与聚类Read & Cluster
超大语料用「头部通读 + 脚本精筛长尾」两段式：头部按权重读到 ≈8（约 850 条），长尾筛低权重长文再精读 30–40 条。约 1/6 阅读量覆盖 ~95% 信号，未读完的部分必须在附录披露。
▼
4
框架抽取Synthesize
提炼认知框架，再跑三件套：4.1 反例对冲 · 4.2 引用溯源 · 4.3 盲区诚实说明。这三条是本项目与一切摘要工具的分水岭，任何情况下不许砍。
▼
5
结构化输出Emit
深度版（默认）/ 标准版 / 极简版三档。深度版含：多章正文 + 共识 vs 争议 + 反例对冲 + 引用溯源 + 行动清单 + 精华句 + 元方法论 + 方法与边界。
▼
6
验证Verify
6.1 引用真实性机验（强制硬门） · 6.2 覆盖度自查 · 6.3 人工校验钩子。差集为空才允许交付。
03 · EVIDENCE

七战实测：方法论是被数据打出来的，不是想出来的

下面每个数字都能在仓库里指到出处：cases/（原始档案）、docs/retrospective.md（沉淀）、docs/rule-provenance.md（规则溯源）。

22%

重复行缺陷

某次抓取 20,399 行里 4,501 行是纯重复。危害不是规模虚高，而是把同一条观点重复计入共识度。

31.9%

楼中楼占条数

却只占点赞量 14.6%（均赞 22.0 vs 一级 60.1）。声音小，但反例与纠错几乎只在这里。

12

高价值评论总赞数

8 条最高价值评论的赞数总和只有 12，而同场最高赞段子单条 236,396。高权重 ≠ 高信号。

七战档案

⚠️ 目录编号 ≠ 战次编号 —— 05-mustwatch-math/ 实际含第 6 + 7 战（同一视频，先抓一级、后全量补抓楼中楼）。

战次规模语料该战验证了什么
第 1 战1,504B站「AI 替代程序员」流水线可行性
第 2 战3,425B站《山》AI 电影两场核心争议专场
第 3 战5,052B站「清北 discouraged」楼中楼捞出一级评论缺失的 7 个议题，其中 4 条直接对冲前文结论
第 4 战8,941薪资 903 + 43 岁被裁 8,038多语料合并产出单语料看不到的洞察；引用机验首次抓到幻觉引用
第 6 + 7 战21,100B站「入站必刷·火柴人 VS 数学」抓到并修复 22% 重复行缺陷；补抓 6,724 条楼中楼后修正正卷 3 条结论
关于「注意力漂移 2.5×」这个数字：一条与视频主题零相关的英语语法争论楼拿到 2,867 赞， 是同场「视频有无教育价值」实质辩论（1,142 赞）的 2.5 倍。但它是单个语料里的单个比值， 在仓库里被明确标记为 [战7·单样本] —— 不能当常数用，唯一用途是提醒「高赞楼 ≠ 议题重要」。
04 · USE IT

三种用法，按你手上有什么选

桌面工具负责把「一个视频链接」变成「一个开箱即用的语料包」； 蒸馏那一步交给你自己选的那个 AI —— 所以不需要任何 API Key。

1

桌面工具（有链接）

下载 exe → ① 采集 → ② 预处理 → ③ 导出蒸馏包 → ④ 引用校验。 第 ③ 步产出一个文件夹，里面既有给 AI 读的语料与方法论，也有可直接粘贴的提示词。

2

装进 agent（有语料）

npx skills add \
  TrueFurina/comment-distillery

把 SKILL.md 装进 Claude Code / Cursor / Codex 等任意 agent， 直接丢给它一份评论 CSV。

3

零依赖脚本（要自动化）

python scripts/prep.py \
  corpus.csv out/
python scripts/verify_citations.py \
  guide.md corpus.csv

纯标准库，可以直接塞进你自己的 CI 或批量管线。

桌面工具的四个页签：① 采集（B 站链接 → 评论含楼中楼 → CSV，支持中途停止、已抓部分照常写出） · ② 预处理（去重/去噪/统计，先看 dup_dropped） · ③ 导出蒸馏包（一键打包，含 PROMPT.md） · ④ 引用校验（幻觉引用差集检测）。
05 · LIMITS

已知局限（写在这里，而不是藏起来）

这一节是本项目最该被读的部分。一个不肯说自己哪里会错的方法论，不值得被信任。

⚠️

判分器只卡形式，不判推断质量

golden/ 的 8 个场景 / 4 类判据检查的是引用是否真实、覆盖率是否诚实、反例是否开采。 一条「引用真实但推理错误」的结论照样能拿满分。这是设计边界，不是 bug。

⚠️

单样本判据不能当常数

「注意力漂移 2.5×」「低赞长文 pasta 污染」等观察只被 1 战验证过， 在 SKILL.md 里被降级标为 [战N·待复现]。 看到这个标记就说明它是假设，不是规律。

⚠️

公开档案只有产物层

cases/ 只包含各战指南与设计文档，原始评论 CSV 不公开 —— 所以你拿不到原始语料来复现我们的跑分。要验证引用真实性，请用你自己的语料跑 verify_citations.py。

⚠️

示例语料是合成的

仓库自带的 examples/sample_corpus.csv 是 26 条合成数据（去噪后 23 条）， 只能演示流水线形状，不构成任何统计意义上的代表性。

还有一条元观察：七战里方法论被数据打穿了 5 次，共同点是 「用代理指标代替真值」 —— 点赞数↔认可度、文本长度↔思考深度、楼层深度↔观点完整性、ID 格式↔引用真实、行数↔语料规模。 完整复盘见 docs/retrospective.md， 被推翻结论台账见 docs/overturned.md。
