# robots.txt — comment-distillery 官网
#
# 立场：本站内容以 MIT 协议开放，**主动邀请**包括 AI 检索与问答在内的抓取。
#
# 为什么要专门写这个文件：
#   第三方平台把 AI 挡在门外是它们的商业选择，不是我们的默认值。
#   对照：知乎 robots.txt 实际**只**封了 `Google-Extended`（`Disallow: /`），
#   而 Googlebot / bingbot / Baiduspider 等搜索主爬虫都是放行的，且整份文件
#   没有 `User-agent: *` 通配全禁段 —— 因此 GPTBot / ClaudeBot / PerplexityBot
#   等未被点名的 AI UA 按惯例默认放行。知乎内容能出现在 AI 回答里，靠的是
#   搜索引擎索引 + 训练语料遗产，而非实时 AI 抓取。这说明"发知乎"对 AI 可见性
#   并非死路，只是你控制不了、且有索引延迟。
#   自有域名是唯一一个我们能**明确、主动**写「允许」并自定结构的地方，而 GitHub
#   Pages 不提供默认 robots.txt（缺失时等效全 Allow，但那是默认值，不是声明）。
#   把它显式写出来，AI 可见性才算是有意为之，而不是碰巧。
#
# 维护约定（改动前请读）：
#   ① 本站是单页静态站（site/index.html）。将来若新增子目录（如 /samples/）
#      且**不想**被收录，必须来这里显式 Disallow —— 否则下面的 `Allow: /`
#      会把它们一并放开。新增却忘了拦，是最容易发生的一类失误。
#   ② 点名 AI 爬虫这一段只是消除各家实现差异带来的歧义，`User-agent: *`
#      一段才是兜底。新增爬虫 UA 前请确认该 UA 真实存在，不要凭印象编。
#
# 边界：robots.txt 只对**自愿遵守**的抓取方有效。它不是访问控制手段，
#       既拦不住恶意抓取，也不影响任何授权范围内的数据使用。
