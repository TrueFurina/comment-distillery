# comment-distillery 开源冲刺路线图

> 目标：把已跑通 4 战的 L3 评论蒸馏 Skill，做成**可开源、能冲星**的 GitHub 项目。
> 本文所有 star 数字来自 2026-09-25 实时检索（GitHub API / star-history / 技能注册表快照），非估算。
> 写作立场：**先校准预期，再给路径**。不灌鸡汤。

---

## 0. 一句话结论（先泼冷水再给路）

**GitHub 高星这件事，方向成立但远非"绝对没问题"。**

品类风口是真的——2026 年 GitHub 全时段 Top-100 里，**16 个是 18 个月内新创建的 agent harness / skill 类项目**，其中 5 个「几乎没有应用代码，就是一堆 Markdown」。Markdown 现在是能直接发货的产品形态。这个窗口对我们极度有利。

**但同类垂直 skill 的两极分化极其残酷**：
- `ui-ux-pro-max-skill`（设计智能）★111K
- `Humanizer`（去 AI 腔写作）★45.9K
- `reddit-insights`（Reddit 评论洞察）★**408**

同样是"给 agent 加一个垂直能力"，差了 270 倍。**决定 star 的不是代码质量，是「需求普适性 × 启动成本 × 分发渠道」三件事。**

我们当前的位置：更接近 408 那一侧（窄场景、先要爬数据、只有中文社区知道）。**要冲高星，必须做一次"场景升维"——这是本路线图的第一优先级，比写代码重要得多。**

## 1. 两条路径的现实评估

### 路径 A：收编入 B站 —— 建议**不作为目标**，只作为结果

| 评估项 | 判断 |
|---|---|
| B站官方 GitHub 组织收编外部项目 | 极罕见。bilibili 组织下多为自研基础设施（Flink 生态、直播弹幕库等），且都服务于自身业务 |
| B站开放平台（open.bilibili.com）应用收录 | 可行但**需要资质审核 + 面向开发者服务**，我们做的是分析层不是平台服务，定位不匹配 |
| 创作中心 / 创作服务市场 | 面向 UP 主的商业化产品位，个人开源项目几乎无入口 |
| 被 B站技术官方账号或头部 UP 主动引用 | **这才是唯一现实路径**，但它不可主动争取，只能是影响力溢出后的结果 |

**结论**：主动追求"被收编"成功率 <5%，且会绑架产品方向（为了迎合平台而做平台想要的功能）。
**正确姿势**：只把 B站当作**首发验证场和最强的 demo 来源**（我们已有 4 个真实案例），把"被 B站生态接纳"当作做好了之后可能发生的**结果**，而不是目标。

### 路径 B：GitHub 开源 + 进 Agent Skill 生态 —— **主攻，且时机对**

三条硬理由：

1. **品类天花板已被验证**：`superpowers` ★263K、`affaan-m/ECC` ★235K、`anthropics/skills` ★165K、`garrytan/gstack` ★125K。全是 Markdown + 少量脚本。
2. **分发渠道已经成熟**：`vercel-labs/skills`（★32.1K）是跨 40+ agent 的 `npx skills add` 包管理器；`skillselion` / `ai-tldr` 等注册表在做 skill 发现。**2026 年装 skill 不再靠手动 clone**——进注册表 = 拿到分发红利。
3. **缺口仍在**：我此前做过全网调研，L1 抓取（MediaCrawler ★6万）、L2 情感统计（红海）都卷完了，**L3"建设性综合"层没有开源、agent-native、输出带引用溯源的厚指南工具**。这个判断经第三方大模型评估也站得住。

## 2. 生态位标定：我们该往哪挪

### 2.1 真实 star 基准（2026-09-25 检索）

| 项目 | Star | 品类 | 对我们的启示 |
|---|---|---|---|
| `obra/superpowers` | 263K | 工程方法论 skill 集 | 天花板由"普适性"决定 |
| `anthropics/skills` | 165K | 官方格式参考实现 | 进官方生态=信任背书 |
| `nextlevelbuilder/ui-ux-pro-max-skill` | **111K** | **单个垂直 skill** | 垂直 skill 也能冲 10 万级 |
| `Humanizer` | 45.9K | 单个写作 skill | "立刻见效"型能力最易传播 |
| `Agent-Reach` | 35K+ | 让 agent 访问 16 平台（含 B站） | **我们最直接的邻居**：它解决"拿到数据"，我们解决"读懂数据" |
| `vercel-labs/skills` | 32.1K | skill 包管理器 | 必须适配的渠道 |
| `cloudflare/security-audit-skill` | 17.6K | 单厂商垂直 skill | 大厂背书 × 明确场景 |
| `reddit-insights` (skill) | **408** | **评论洞察 skill** | ⚠️ **警示样本**：和我们最像，星最少 |
| MediaCrawler | ~60K | 多平台爬虫(L1) | 我们要复用的上游 |

### 2.2 关键判断：为什么 `reddit-insights` 只有 408 星

拆解它和我们当前的相似度——**几乎一模一样**：
- 都是"抓某个平台的评论 → LLM 提炼要点"
- 都要先有数据源 / API key
- 都面向"想做研究的人"而非"所有知识工作者"

**它卡在三件事上**：
1. **场景窄**：只有做营销/选品的人需要，且这些人往往用商业 SaaS（CommentGrid 之类）；
2. **启动成本高**：先配 API key → 再跑 → 才能看到价值，第一屏没有"哇"；
3. **名字符号弱**：`reddit-insights` 是个描述，不是一个概念。

对应到我们：`comment-distillery` 名字已经赢了（**"蒸馏"是有画面感的概念，不是描述**），但我们仍卡在第 1、2 条。

### 2.3 场景升维：这是全篇最重要的一条建议

**把定位从「B站评论 → 指南」升维成「任何群体文本 → 带引用的可行动认知」。**

| 维度 | 当前（窄） | 升维后（宽） |
|---|---|---|
| 价值主张 | 分析 B站评论区 | **把一堆人说的话，炼成一份可落手的认知** |
| 输入 | B站 CSV | CSV（任意来源）+ Reddit JSON + YouTube 导出 + 知乎/V2EX + **问卷开放题 + 会议记录 + 用户访谈 + Notion 导出** |
| 受众 | 想研究舆情的人 | **产品经理做用户研究、研究者做质性分析、创作者找选题、学生做文献综述、运营做复盘** |
| 传播句 | "分析 B站评论" | **"Turn 3,000 messy comments into a cited, actionable guide — in one command"** |

**为什么必须这么做**：
- 窄定位的天花板就是 `reddit-insights` 的 408；
- 宽定位的天花板是"质性分析（qualitative analysis）的 agent 化"——这是一个**所有人文学科 + 所有做用户研究的岗位**都存在的真需求，现有工具（NVivo、MAXQDA）又贵又重又不带 LLM；
- 我们的核心技术（反例对冲、盲区说明、引用溯源、分层输出）**对任何群体文本都成立**，不是 B站专属——方法论本来就是平台中立的，只是没升维。

**代价**：README 要重写、要多做 2-3 个输入适配器。**收益**：潜在用户池从"爬虫玩家"扩到"所有做质性研究的人"，量级差两个数量级。

## 3. 合规：我们有一个被低估的天然优势

**"不写爬虫、只做 L3"这个差异化决策，意外给了我们一个巨大的合规红利**——这一点必须在 README 里大写。

| 风险项 | 我们 | MediaCrawler 类爬虫项目 |
|---|---|---|
| 反爬 / 绕过风控代码 | **零行** | 核心资产 |
| 登录态 / Cookie 处理 | 不使用（公开接口即可） | 必需 |
| 限速绕过选项 | **明确不提供** | 常见 |
| 平台协议风险 | 低（只用公开只读接口 + 默认限速） | 中高 |
| 企业可用性 | **可用** | 多数标"非商用学习许可" |

**这意味着**：项目可以 MIT 开源、可以被企业放心用、可以进 awesome 列表而不引发争议、不会被平台发 DMCA。

**但仍要做的三件事（红线）**：
1. `fetch_bilibili_comments.py` 放进 `contrib/` 或 `adapters/`，README 明确标注「可选桥接，非项目核心」——主仓核心是**分析层**；
2. 合规声明前置到 README 顶部：仅个人学习研究、遵守 robots 与平台规则、禁止商用舆情监控与批量用户画像、原始数据不得二次分发；
3. **示例数据集脱敏**：现在 4 个视频的评论 CSV 含 UID，进仓库前必须去掉用户标识字段（只留 ID/赞/楼层/文本/时间）。

## 5. 分发策略（决定 star 的 80%）

按 ROI 排序：

| 优先级 | 渠道 | 动作 | 预期 |
|---|---|---|---|
| **P0** | `vercel-labs/skills` 注册表 | 让 `npx skills add <repo>` 可用 | 拿到跨 40+ agent 的分发 |
| **P0** | awesome 列表 | 提 PR 进 `ComposioHQ/awesome-claude-skills`（★18.9K）等 | 稳定长尾曝光 |
| **P1** | Reddit `r/ClaudeAI` / `r/LocalLLaMA` | 发 Show & Tell，标题用传播句 | 英文社区第一波 |
| **P1** | X / 中文社区（V2EX、掘金、少数派） | 同步发，中文社区转化高 | 中文基本盘 |
| **P2** | 写一篇方法论长文 | **"Why comment sections are the most underrated dataset"**——把第 11 章元方法论扩成博文 | 长尾搜索流量 |
| **P2** | 与上游项目互引 | 在 MediaCrawler / Agent-Reach 的 issue/讨论里提"分析层搭档" | 精准导流 |

**最容易被忽略但最有效的一条**：P2 的方法论长文。star 本质上来自"这个人提出了我没想到的角度"，不是"这个工具好用"。我们有《元方法论》那一章的原创内容（高赞≠高信号、四道盲区、评论区=免费专家圆桌），这是别人没有的**思想**，应该拿它去换传播，而不是只发一个工具 README。

## 6. Star 目标：三档诚实设定

| 档位 | 目标 | 达成条件 | 我的概率估计 |
|---|---|---|---|
| **保底** | 300–800 | 仓库体面 + 进 2-3 个 awesome 列表 + 中文社区发一轮 | **80%** |
| **合理** | 3K–8K | 完成场景升维 + 进 skills.sh + 英文社区有一篇爆帖 | **35–45%** |
| **乐观** | 20K+ | 踩中品类风口 + 被大 V/官方引用 + 方法论长文出圈 | **8–12%** |

**我为什么不给"绝对没问题"**：`reddit-insights` 就是活生生的反例——同样的想法、同样先发的 Reddit 生态，408 星。**能不能起量，三件事说了算：场景升维做不做、英文 README 写不写、分发渠道走不走。** 代码质量只占很小权重。

## 9. 需要你拍板的三个决策

1. **场景升维做不做？** 我的强烈建议是做——窄定位天花板就是 408 星。代价是多花 1 周。
2. **fetch 脚本是否进主仓？** 建议进 `contrib/` 并标注可选，既保留端到端体验，又把合规风险隔离在主仓之外。
3. **仓库归属？** ~~建议用中性组织名~~ → **已撤回该建议（2026-09-26 修正）**。复核后发现：本赛道所有对标项目**全在个人账号下**——MediaCrawler（NanmiCoder）、Agent-Reach（Panniantong）、youtube-comment-downloader（egbertbouman）。个人号是这个品类的**常态而非缺陷**；组织的边际收益只是 namespace 观感，成本却是手动建组织 + transfer 风险，且个人号的动态曝光反而有利于早期被发现。**结论：保持个人仓库 `TrueFurina/comment-distillery`，不做 transfer**；仅当未来形成多仓库 skill 家族时再考虑组织。
