# examples/

## `sample_corpus.csv` — 合成示例语料

**⚠️ 这份数据是人工合成的，不含任何真实用户数据、真实凭据或真实平台内容。**

它是为了让你能在**没有任何真实语料**的情况下把整条流水线跑通一遍而设计的，同时也作为 CI 的回归测试输入。

### 它刻意包含了流水线要处理的所有情况

| 现象 | 样例条目 | 用来验证 |
|---|---|---|
| 高权重零信息量 | `c1001`（"前排打卡哈哈哈"，842 分） | "**高权重 ≠ 高信号**"——排名最高的往往不是最有内容的 |
| 广告（去噪） | `c1007`、`c1026` | 噪音关键词与纯链接过滤 |
| 过短（去噪） | `c1008`（"哈"） | 最小长度过滤 |
| 低权重长文（真信号） | `c1006`、`c1011`、`c1012`、`c1017`、`c1023` | `low_score_long.txt` 的价值——认知框架藏在低分长文里 |
| 楼中楼反驳 | `c1004`、`c1010`、`c1019`、`c1025` | **反例对冲**：子回复直接反驳顶层观点 |
| 层级结构 | `parent_id` / `is_reply` 列 | 一级 / 回复的区分与统计 |
| 时间跨度 | `created_at` 09:00 → 13:00 | 时间切片分析 |

### 跑一遍看看

```bash
python scripts/prep.py examples/sample_corpus.csv /tmp/cd-demo

# 预期：26 条 → 去噪 23 条（剔掉广告 2 条 + 过短 1 条）
cat /tmp/cd-demo/stats.json
cat /tmp/cd-demo/low_score_long.txt      # ← 真信号区
```

### 用真实语料替换它

只要你的 CSV 有 `id` 和 `text` 两列就能跑，其余字段见 [`../docs/canonical-format.md`](../docs/canonical-format.md)。

### 为什么放合成数据而不是真实案例

本项目的合规约束里有一条：**不得二次分发原始语料**。把真实的评论 CSV 打包进开源仓库，本身就是这条规则的违反。

所以这里用合成语料演示能力；真实战绩记录在 `../SKILL.md` 的「首测数据集」一节（只描述规模与结论，不附数据）。
