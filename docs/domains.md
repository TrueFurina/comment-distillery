# 语料域适配指南

流水线是同一套，但**不同语料的偏差结构不同**——误读的方式不一样，读法就要跟着调。

本文件按域给出：**特征 → 主要陷阱 → 读法调整 → 产出差异**。

---

## 通用读取策略

| 语料规模 | 策略 |
|---|---|
| < 1500 条 | 全量逐条通读 |
| 1500 – 5000 条 | 头部通读（读到权重≈5–8）+ 低权重长文精筛 |
| > 5000 条 | 同上，且**必须**在附录披露"未逐条读完的部分" |

---

## 1. 社区评论区（B站 / YouTube / Reddit / 知乎 / 小红书 / 微博）

**特征**：大量、短、口语化、带梗；权重（点赞）分布极度长尾；有"楼中楼"层级；算法推流会造成跨圈层涌入。

**主要陷阱**
- **头部被"最大公约数"占据**：词义科普、玩梗、附和、形式吐槽（用词/口音/长相/标题句式）。实测某视频 12317 赞的第一名是零信息量的词义解释，而全篇最重要的认知框架只有 4 赞。
- **meta 噪音**：头部在争论**形式**而非内容，说明该内容被推给了非目标受众，真观点被稀释在中腰部。
- **最高赞 ≠ 多数意见**：是"最易被点赞的表达"，不是"最多人认同的立场"。
- **幸存者偏差最重**：被议题彻底击垮、离开该领域的人，不会回来评论。

**读法调整**
- **两段式**：头部通读锚定情绪基调 + `low_score_long.txt` 捞真框架。两头都不能漏。
- **楼中楼单独处理**：子回复里常有一级吵不出来的反驳与澄清（实测 3551 条楼中楼里捞出 7 个新议题，**4 条直接推翻了基于顶层得出的结论**）。至少对 `reply_count>=3` 的讨论楼补一轮。
- meta 噪音**本身可以是有价值的发现**（它证明了某种群体状况），但必须**标注为"噪音"**，不能当作观点采纳。

**产出差异**：这是"反例对冲"机制价值最高的域——因为争论密集，反方论据天然充足。

## 2. 问卷开放题

**特征**：无权重、无层级、无回复；回答者是被**提问引导**的，不是自发的；常有一题多答、答非所问、敷衍作答（"无""没有""还行"）。

**主要陷阱**
- **提问框架效应**：问卷的措辞会塑造答案分布——同一议题换个问法，结论可能翻转。**必须把问卷原题写进指南**。
- **代表性幻想**：问卷回收率与样本自选偏差常常被忽略（谁更愿意填问卷？）。
- **敷衍作答污染**：大量低信息回答会把主题分布"平均化"。

**读法调整**
- 用**饱和度**而非权重判断停止点：读到"新主题不再出现"为止。
- 先做**低信息回答剔除**（"无/没有/还行/不知道"），但要披露剔除了多少、占比多少。
- 按**题目**分组分析，不要把所有题目的答案混成一锅——每题是一个独立议题。

**产出差异**：不需要"反例对冲"的争论结构（问卷里没有辩论），改为**"少数意见专区"**——主动保留占比低但逻辑完整的回答。

## 3. 访谈逐字稿

**特征**：小样本、深内容、有提问者干扰、有口语冗余（"嗯""那个""就是说"）、时间顺序有意义。

**主要陷阱**
- **把提问者的框架当成受访者的观点**（最常见）。
- 单例过度推断：一个人的一段话不能代表一个群体。**访谈语料的价值在深度，不在广度**。
- 忽略**访谈情境**（什么时间、什么关系、什么环境下说的）。

**读法调整**
- 先**切分角色**：主持人 vs 受访者（`author_id` / `source` 标记或人工）。
- 逐主题聚类，但**每个结论都要标注"来自几位受访者"**——一个人说的不写成"大家认为"。
- 保留**原话的语境**（引用时带上下文，不要截断成金句）。

**产出差异**：规模小、密度高，**极简版/标准版通常更合适**；深度版容易变成逐段复述。产出应偏"观点地图"而非"统计画像"。

## 4. 产品反馈（应用商店评论 / NPS / 客服工单）

**特征**：高度情境化（版本、机型、付费状态）；负面偏置明显（不满的人更愿意写）；含大量重复模板。

**主要陷阱**
- **负面偏置**："评分"与"真实满意度"不是一回事。
- **版本混淆**：不同版本的反馈混在一起分析，会得出互相矛盾的结论。**必须按版本/时间切分**。
- 把**功能请求**当成**问题描述**（"希望支持导出" ≠ "导出坏了"）。

**读法调整**
- 按 **版本 / 平台 / 客群分层**后再聚类；跨版本结论必须标注版本范围。
- 区分三类：**Bug 报告 / 功能请求 / 情绪表达**——它们的行动含义完全不同。
- 权重（有用票/赞）在商店评论里通常很低，别指望排序。

**产出差异**：行动清单是主菜——这类语料的终点天然是"下一步做什么"。

---

## 5. 开源社区（GitHub Issue / PR 讨论）

**特征**：技术密度高、有明确的对立立场（维护者 vs 用户）、有决策上下文（RFC / breaking change）、信息可交叉验证（代码是事实来源）。

**主要陷阱**
- **把"最高赞 comment"当成"已决策"**——决策在 maintainer 手里，不在反应数里。
- 忽略**时间线**：一个 3 年前的 issue 的结论可能已被后续 PR 推翻。
- 用户身份敏感：**产出中不要带 `@username`**。

**读法调整**
- 用 `created_at` 建立**时间线**，标注最后状态（open / closed / superseded）。
- 区分**立场**（观点）与**事实**（可验证的代码行为）——后者优先。
- 对"为什么这样设计"类问题，**主线叙事 + 反方**结构最有效（功能取舍天然有 trade-off）。

## 6. 团队协作（会议纪要 / 群聊 / 复盘）

**特征**：有明确角色与权力关系；大量"过程性发言"（安排、确认、寒暄）；决策往往隐含而非明写（"那就这样吧" = 通过）。

**主要陷阱**
- **把"说了"当成"定了"**：会上提出 ≠ 达成共识。
- 忽略**权力结构**：谁说的可能比说了什么更重要（一句来自负责人的话与一句来自新人的话，权重完全不同）。
- 隐私与政治风险最高——**这类语料默认不应公开产出**，只做内部使用。

**读法调整**
- 显式区分：**决策 / 待办 / 分歧（未决） / 过程噪音**。
- 标注**角色**（主持人 / 决策者 / 执行者），但**匿名化**。
- 对"未决分歧"单独成节——这是这类语料最有价值的产物。

**产出差异**：行动清单 + 未决清单为主；不追求"共识"，因为团队文本的共识常常是表面共识。

---

## 7. 直播弹幕 / 实时评论

**特征**：极短、极高重复（刷屏梗）、强实时情绪、几乎无独立观点。

**主要陷阱**
- **重复即噪音**：同一条梗刷 500 次不等于 500 个人认同。
- 极短文本占比极高，去噪会丢掉大部分内容——**要披露剔除比例**。

**读法调整**
- 必须**先去重**（按文本去重统计"独立表达数"），再谈频次。
- 把弹幕当作**情绪温度计**而非观点来源；观点要去话题更完整的语料里找。
- 去重后按 `author_id` 看**独立发言人数**，避免单一用户刷屏主导结论。

**产出差异**：适合**极简版**；或与评论区语料**合并**使用（弹幕提供情绪强度，评论提供观点结构）。

---

## 8. 跨域原则（三条）

1. **偏差结构决定读法**——不是"什么都按评论区的读法办"。评论区防"高权重陷阱"，问卷防"提问框架"，访谈防"单例外推"。
2. **规模决定策略**——小语料全读，大语料两段式，且必须披露未读部分。
3. **产出形态跟着语料走**——不是每份语料都该产出"深度版厚指南"。访谈和弹幕常常更适合标准版/极简版。**默认深度版是给"大语料 + 强争论"场景定的**，遇到小语料要主动判断。
