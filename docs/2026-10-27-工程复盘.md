## 0. 一句话结论

**用户报的问题是「根本不能运行」，但真正的问题不是"没做完"，而是"149 个测试全绿、界面却点不动"。**
根因在于**测试覆盖的是后端逻辑，没人测过"在浏览器里真的点一下"**。

这条比任何一个具体 bug 都重要：它说明"测试通过"只能证明被测过的东西。

## 1. 最先该记的三件事

### 1.1 最致命的问题，是"看起来正常"

CSP 写成 `default-src 'none'` 却没写 `connect-src`，浏览器据此**拦掉页面上所有 `fetch`**。

它的恶劣之处在于表现：

- 页面画得完整；
- 自检徽章是绿的；
- 五个页签都在；
- **任何按钮点下去都毫无反应**。

控制台只有一行 `blocked`。用户（和我最初）都会以为"程序卡了"，而不是"有一个请求被安全策略拦了"。

> **教训**：安全策略的默认拒绝，最容易伤到自己人。凡是写 `default-src 'none'`，必须逐项列出实际要用的 `connect-src` / `img-src` / `script-src`，并在真浏览器里点一遍。

### 1.2 没被测过的那条路，恰恰是用户唯一走的那条

`on_progress(done, total)` 比上游约定少一个形参（应为 `done, total, subs`）。

- GUI 端当年写的是三参 → 桌面版正常；
- **Web 端写的是两参 → 一跑必崩**。

而测试从没跑过 `crawl`（要联网），所以这个"必崩"躲过了 149 个测试，**而且是在抓满 4,900 条、等满 3 分钟之后才崩** —— 用户白等一场。

> **教训**：跨模块回调的**签名一致性**必须有测试。最省事的做法不是发网络请求，而是 `inspect` 一下调用约定 + 断言上游参数名。

### 1.3 "能跑"和"能用"中间隔着一整层

本轮修的 20 多个问题里，只有 3 个是"崩"。其余都是：

| 类型 | 例子 | 用户感受 |
|---|---|---|
| 没有反馈 | 采集时 4 分 44 秒一个字都不打 | 以为卡死 |
| 不能中止 | Web 端完全没接 `should_stop` | 只能干等 |
| 停了白停 | 停止后已抓的 1298 条被丢弃，写出 0 条 | 比不能停更气人 |
| 拿不到手 | 报告生成了但返回 `files` 为空，界面点不开 | 以为没出结果 |
| 按钮死了 | `setBusy` 把"运行中…"存成原件标签 | 永远在跑 |
| 默认值错 | 输出框被预填成**目录**，写盘必抛 PermissionError | 莫名其妙失败 |
| 容量不够 | 高 DPI 下窗口装不下内容，「开始采集」被挤出可视区 | 找不到按钮 |

**没有一个会抛异常，但没有一个能让用户顺利用完。**

## 2. 我自己犯的错（比修的 bug 更值得记）

这轮我在"证明自己改对了"这件事上翻车了四次，模式高度一致：

### 2.1 用截图当证据 —— 两次都截错了对象

为证明"exe 里有了一键页"，我截图。两次都抓到了**盖在上面的浏览器窗口**，图里明晃晃的「⚡ 一键完成」页签其实是 Web 版的。

更糟的是我还据此推论"窗口被压缩到 735×544、右侧被裁" —— `GetWindowRect` 返回**物理像素**，200% 缩放下与 tkinter 逻辑像素差约 1.5 倍，那个结论是假的。

> **改法**：让程序自己报告。`--selftest-gui` 现在输出 `TABS:` / `SELECTED:` 并支持 `--report` 落盘，exe 产物自己说出它有哪几个页签。

### 2.2 判据写了，但漏了最常见的写法

我加了「界面页签 == 文档」机验，然后做变异验证：把 README 改回"四个页签" —— **一条都没报**。

因为正则写的是 `\d+ 个页签`，而**中文文档最自然的写法是"四个页签"**。判据等于没生效。

### 2.3 判据跑了，但被 SKIP 了

同一项的自检变异显示 SKIP：变异跑在临时副本里，副本没有 `app/`，解析不到页签 → "环境不满足，跳过"。

**一个永远 SKIP 的检查，和没有这项检查是等价的**，但它在报告里显示为绿色。

### 2.4 同一个防御写了三遍

GBK 下 `print("✓")` 抛 `UnicodeEncodeError`。这个坑先后在 `build_exe.py`、`webui.main`、`gui.smoke_test` 各修一次，每次都是"哪报错修哪"。

第三次才想到根因：**没有唯一入口**。`app_main.main()` 是所有 exe 命令的必经之路，放那儿一次就够了。

> **判据**：同一种防御需要写第二遍，就说明缺一个统一入口 —— 别复制第三份。

**四个错的共同点**：都是"我确认过了"。真实可靠性来自**能被机器重新执行的断言**，不来自我的确认。

## 3. 有效的做法（值得沿用）

1. **变异验证是分水岭**。每个新增测试都回退修复、确认变红。上面 §2.2 / §2.3 两个失效的判据，全是靠这一步抓到的 —— 正常跑永远显示绿色。
2. **让产物自己说话**。`--selftest-gui --report` 输出真实页签；`build_exe.py --verify` 逐项比对 11 个随包资源的 SHA-256。都不依赖任何人的眼睛。
3. **把"文档落后"变成门**。项目原有 10 项机验，本轮加了第 11 项「界面页签 == 文档」。三次都是它拦住了我漏同步的测试数 —— 它比我可靠。
4. **端到端真跑一遍**。一键流程实测（四组都真跑，非估算）：

   | 路径 | 耗时 | 规模 |
   |---|---|---|
   | Web 主楼 | 229 s | 4,938 条 → 去噪 4,609 |
   | Web 含楼中楼 | 677 s | 10,072 条 → 去噪 9,537（主楼 4,942 / 楼中楼 5,130） |
   | GUI 主楼 | 234.9 s | 4,613 条 |
   | GUI 含楼中楼 | 619.8 s | 9,541 条（主楼 4,610 / 楼中楼 4,931） |

   然后拿这份**真实语料**写一篇指南，用 `verify_citations.py` 验：14 条引用、0 幻觉；再注入一条假引用，必须被拦。两个方向都验，才算闭环。

## 4. 用户提出的两条需求，改变了产品形态

### 4.1 「应该一键完成全部工作的」

原来的五步流水线是**照着 pipeline 设计的**，不是照着用户设计的。多数人只想"放进去、拿出来"。

现在 GUI 与 Web 都默认停在 **⚡ 一键完成**：填个链接 → 一次跑完 ①采集 ②预处理 ③蒸馏包 → 拿到能直接喂给 AI 的成品包。

终点刻意停在"包"，不加 ④⑤：**写指南的是用户自己的 AI**（本工具不内置模型、不收 Key）。硬串进来只会做出一个没有输入的空转环节。

### 4.2 「为什么不是 E 盘？不要 C 盘！」

默认输出原本硬编码成 `Path.home()/"comment-distillery-output"`，**散写 5 处**。结果程序在 E 盘、产物在 C 盘，同一个项目的文件分两个盘。

现在统一 `core.default_outdir()` → `<程序目录>/output/`。

其中有个关键区分差点做错：打包后 `resource_root()` 是 `_MEIPASS`（临时解包目录、**退出即删**），拿它当输出位置会让每次运行的文件换个地方、甚至写完就没。真正稳定的是 `sys.executable` 所在目录，故新增 `core.app_root()`。

历史 29MB / 190 个文件已逐个校验大小后迁到 `output/_migrated-from-C/`，确认无缺后才删原目录。

## 6. 给下一个接手的人

1. **先跑 `scripts/check_doc_consistency.py`**。11 项里任何一项红，都说明文档已经和事实脱节，先修它。
2. **改完必跑 `--self-test`**。它验证的是"判据本身还有效"，22 个变异必须全拦。
3. **加了测试就同步 6 处测试数声明**，否则机验会红。别改检查脚本去迁就文档。
4. **别用截图证明产物**。让程序打印。
5. **重发 exe 后必须跑三件**：`--selfcheck`、`--selftest-gui --report`、`build_exe.py --verify`。构建脚本自己都写了"务必都跑一遍再宣称成功"。
