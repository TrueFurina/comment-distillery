## 2. 方法论演进：被推翻的五次

这是全文最重要的一节。**每条都写"当时相信什么 → 被什么数据打穿 → 现在怎么做"。**

### 修正 1：「高赞 = 高信号」❌
- 当时：按赞降序读头部就能拿到主要观点。
- 打穿（第六战）：**8 条最具价值的评论，赞数总和只有 12**；而最高赞段子单条 **236,396**。两个数量级差了 4 个量级。
- 现在：头部只用于**锚定情绪基调**；真信号必须用脚本筛"低权重 + 长文"专门开采。

### 修正 2：「低赞长文 = 真信号区」⚠️（部分失效）
- 当时：修正 1 之后，把低赞长文当成金矿区。
- 打穿（第七战）：低赞区混入大量**粘贴板 pasta**——鸿蒙长文、歌词、游戏攻略、小说片段，甚至有作者自述"不小心又粘贴板了"。
- 现在：规则加人工判据——**优先"有具体指称"的长文**（提到具体知识点 / 论据 / 来源），跳过"无指称的叙事性长文"；可用"同一用户短窗口内连续 ≥3 条长文"自动标记可疑。

### 修正 3：「只抓一级评论就够」❌
- 当时：`--roots-only` 抓一级，规模够大就行。
- 打穿（第七战）：补抓 6,724 条楼中楼后，**正卷 3 处结论被修正**（见 §3）。反例、专业纠错、事实核查几乎**只存在于**楼中楼。
- 现在：楼中楼是**必需项，不是可选补充**。采集受限时至少补 `reply_count>=3` 的讨论楼。

### 修正 4：「评论真实性靠人工核对」❌
- 当时：写完自己检查一遍引用 ID。
- 打穿（第四战起）：幻觉 ID **格式完全正确、看起来毫无破绽**——第四战 96 条里 1 条，第六战 103 条里 1 条（索引里写错一位数字）。
- 现在：交付前**必须**跑 `verify_citations.py`，差集非空不许交付。这是本 skill 唯一用脚本卡死的质量门。

### 修正 5：「重复行只是规模虚高」❌
- 当时：发现 22% 重复，第一反应是"数字不好看"。
- 真正的危害：**同一条观点被重复计入共识度**，直接污染"高赞即共识"的判断——这不是美观问题，是**结论错误**。
- 现在：抓取端按 `rpid` 去重 + `prep.py` 去噪前按 ID 去重 + `stats.json` 报 `dup_dropped`；交付前必查 `unique_id_count == row_count`。

## 3. 可复用的量化判据（带实测来源）

这些数字是**跨议题的结构性发现**，不是个案。新建语料时可拿来当基线对照。

| # | 判据 | 实测值 | 用途 |
|---|---|---|---|
| Q1 | **广场 / 走廊比**：楼中楼占条数 vs 占赞数 | **31.9% / 14.6%**（均赞 22.0 vs 一级 60.1） | 判断"声音小但信息密"的层有多大；比值越悬殊，越不能只抓一级 |
| Q2 | **注意力漂移比**：跑题议题的赞 / 实质议题的赞 | **2,867 / 1,142 = 2.5×**（英语语法争论楼 81 条 vs 教育价值辩论 69 条，后者才是视频主题） | 给"评论区在讨论什么"降温：最热的楼可能和主题零相关 |
| Q3 | **赞-信号背离**：最高价值评论赞数和 vs 最高赞噪音 | **12 vs 236,396** | 支撑"必须专门开采低赞区" |
| Q4 | **低赞长文筛选率** | 7,886 → **486**（6.2%） | 预估精读工作量 |
| Q5 | **去重率** | 20,399 行中 **4,501 行重复（22%）** | 抓取后必查项 |
| Q6 | **阅读覆盖率** | 正卷精读 429 / 14,526 = **3.0% 条数** | 诚实声明的口径 |
| Q7 | **幻觉率**（机验抓到的） | 96 条里 1 条 / 103 条里 1 条（**约 1%**） | 说明"人工自查"必然漏掉它 |

## 4. 交付质量门（每条都可执行）

| 门 | 检查 | 不通过怎么办 |
|---|---|---|
| G1 | `verify_citations.py` 差集为空 | **不许交付**，替换真实条目后复验 |
| G2 | `unique_id_count == row_count` | 回去查去重链路 |
| G3 | 有**覆盖率诚实声明**（精读条数 / 总条数 + 未读部分不做断言） | 补写 |
| G4 | 有**反例对冲**章节，且提出反方时同时给出反-反方 | 补写；一级无反例时必须去楼中楼开采 |
| G5 | 数字**单一真值**（不手写漂移，全部来自脚本输出或实测） | 逐条回溯到源文件 |
| G6 | 无 PII（真实姓名 / 账号 / 联系方式 / 精确位置） | 脱敏 |
| G7 | 规模 >5000 走**两段式阅读**并披露未读部分 | 补做或降级声明 |

## 5. 与 AGI-Distiller 的对照学习

`E:\Program\AGI-Distiller` 是同作者的另一个蒸馏项目（单篇技术长文 → 可执行 SKILL.md）。两者共享"蒸馏"骨架但输入/产出正交，可互相搬运的东西不少。

| 维度 | AGI-Distiller | comment-distillery | 搬运方向 |
|---|---|---|---|
| 输入 | 单篇长文 | 群体文本（N 人说同一议题） | — |
| 产出 | 可执行 skill | 带引用厚指南 | — |
| **沉淀门槛** | **频次制**：痛点被 1 篇提到→notes，2 篇→memory，3 篇→行为规范，重复 3 次→skill | **单战即升级**（第七战一条发现就直接写进 SKILL.md） | ⬅ **我们该学它**：单战升级容易把个案过拟合为铁律。应加"同一发现出现 ≥2 战才进 SKILL.md，出现 1 战先进 cases/notes" |
| **质量评估** | **golden 测试集**：场景(yaml) / 判分器(graders.py) / 跑分器(shell) 三分离；离线 `--replies <dir>` 判分；加权百分制 + 跨版本对比 | 只有 `verify_citations.py` 单门 | ⬅ **最值得搬**：见 §6 |
| **拒稿归档** | `skills-drafts-archive/rejected/` 显式保存被否掉的草稿 | 被推翻的结论散落在增补卷里，无独立机制 | ⬅ 应建"被推翻结论台账"（七战已有 5 条，见 §2） |
| 交付门禁 | 7 条清单（frontmatter / 代码块 / 触发词 / 跨 CLI 兼容…） | 无成文清单 | ➡ 我们已有 G1–G7（§4），可反向输出给它 |
| **输入可溯源机验** | 无（源是单篇，不需要） | **有**：引用 ID 与原始 CSV 做差集 | ➡ **反向输出**：若它未来做多源合并蒸馏，会立刻需要这套机验 |
| 分发 | 7 平台兼容表 + marketplace / `npx skills add` | 路线图已列，未落地 | 两边可共用同一份渠道清单 |

**最值钱的一条**：把 AGI-Distiller 的 golden 三分离设计搬过来（见下节）。

## 6. golden 评估集（**已建** → 详见 [`golden/README.md`](../golden/README.md)）

**为什么必须做**：只能证明"这份指南的引用是真的"，**证明不了"这份指南变好了"**。换模型 / 改 SKILL.md / 调筛选参数后有没有变强——全靠感觉。七战攒下的经验需要一个可回归的载体，否则它们会随着会话结束蒸发。

**已落地（2026-09-26）**：

```
golden/
├── cases/*.json        场景集（纯数据）—— 格式用 JSON 不用 YAML：零依赖是硬约束
├── graders.py          判分器（复用 scripts/verify_citations.py，不重写）
├── run_golden.py       跑分器（--replies 离线判分 / --baseline / --self-test / --compare）
└── replies/baseline/   理想回复（应拿满分，同时是变异验证的原料）
```

**实测**：8 个场景 / 4 类，baseline 跑分 **100.0 / 100**；变异验证 **31 个变异体全部被正确扣分**；已接入 CI（`--self-test` + `--baseline` 两步）与回归测试（`tests/test_golden.py`，12 个用例）。

**为什么必须有变异验证**：测试全绿 ≠ 判分器有效——一个永远给满分的判分器能让所有测试通过。所以 `--self-test` 会派生"故意违反"的回复（删关键词 / 插禁词 / 把引用 ID 换成不存在的 `c9999999`），**变异体还拿满分就判判分器无效，退出码 1**。

四类场景（对应 §2 的五次修正，每条都有真实出处）：

| 类别 | 场景示例 | 判据 |
|---|---|---|
| `citation` 引用真实 | 给一段语料，要求产出带引用结论 | 所有 ID 必须与语料差集为空 |
| `coverage` 覆盖率诚实 | 给 5000 条语料要求出结论 | 必须声明未读部分；不得出现"评论区普遍认为" |
| `counterevidence` 反例开采 | 给一片**全正向**语料 | 必须给出反例章节；一级无反例时必须要求补楼中楼 |
| `layering` 辩论层意识 | 只给一级评论 | 必须披露"缺辩论层"这一盲区（第六战附录 B 的真实教训） |

**离线判分模式优先**（`--replies <dir>`）：把 agent 回复存成文本文件再判分，**不绑定任何特定 CLI 或模型**——这一点是 AGI-Distiller 设计里最聪明的地方，直接抄。

## 7. 已知局限（诚实清单）

1. **全部语料来自 B 站单一平台**。跨平台结构（YouTube 的嵌套回复、Reddit 的投票排序、知乎的折叠机制）是否会让 Q1/Q2 失效，未验证。
2. **"真·人工校验 loop" 从未实现**。现在的机验只卡引用真实性与格式，**不检验结论质量**——一条引用真实但推断错误的结论能完整通过所有门。
3. **golden 评估集已建（§6），但只判形式与可溯源，不判推断质量**。一条"引用真实但推理错误"的结论能拿满分。因此"第 N 版 SKILL.md 比第 N-1 版强"这句话，**只在 4 类已覆盖维度上可支撑**，不是整体质量的证明。
4. **单战升级问题**：§5 指出的方法论过拟合风险，当前 SKILL.md 里的规则多数只被 1 战验证过。
5. **注意力漂移（Q2）只有 1 个样本**。2.5× 这个比值来自单条楼，不能当常数用。
