# 被推翻结论台账（Overturned Claims）

> 建立：2026-09-26（P2）
> 这份文件是**反例的元反例**——`docs/retrospective.md` §2 记录了我们被数据打穿的五次，
> 本文进一步为每条**写明"未来什么证据会再次推翻它"**。
>
> 为什么值得单独存：一条结论被推翻一次，不代表它现在就对了。
> **如果一条规则无法说清"什么情况下我会再次承认它错了"，那它只是换了个方向的教条。**

| 字段 | 含义 |
|---|---|
| 曾经相信 | 当时写进 SKILL.md 的原文口径 |
| 被什么打穿 | 具体数据 / 具体条目，可溯源 |
| 现在怎么做 | 修正后的规则 |
| **再次推翻的条件** | 出现什么证据时，这条也该被撤下 |

---

## OT-1 「高赞 = 高信号」→ 已推翻

- **曾经相信**：按点赞降序读头部，就能拿到主要观点。
- **被什么打穿**：战3 最高赞（12,317）是"discouraged 是泄气的意思"这种词义科普，而最重要的认知框架只有 4 赞；战6 里 8 条最高价值评论的赞数总和只有 12，同期最高赞段子单条 236,396。
- **现在怎么做**：头部通读定情绪基调，**再单独用脚本筛低权重长文**捞真信号，两头都不漏。
- **再次推翻的条件**：
  1. 若出现一个语料，其**低赞长文区完全没有可用信号**、且核心结论全部来自头部 —— 说明"低赞 = 真信号"只是特定圈层的现象；
  2. 若某平台取消公开点赞数或改为算法隐藏权重，本条的输入（`score`）本身失效，规则应改为基于"被回复数"排序。
  3. ⚠️ 当前反方向的风险已在战7 暴露：低赞区会混入**粘贴板污染**（见 W4），说明"低赞"这个筛选维度本身不干净。

---

## OT-2 「低赞长文 = 真信号区」→ 部分失效

- **曾经相信**：`权重≤8 且 字数≥120` 的筛选能稳定捞出真知灼见。
- **被什么打穿**：战7 低赞长文区混进大量粘贴板 pasta（鸿蒙长文 / 歌词 / 游戏攻略），且**有作者自述"不小心又粘贴板了"**——长文 ≠ 有信息。
- **现在怎么做**：追加人工判据，优先看**有具体指称**的长文（提到具体知识点/论据/来源），跳过无指称的叙事性长文。
- **再次推翻的条件**：
  1. 若"有具体指称"这条判据在后续语料里**同样捞到大量伪造细节的长文**（AI 生成或复读），则需要引入"可交叉验证性"作为第二判据；
  2. 若出现平台使长文本身变稀缺（如字数限制收紧），该筛选维度失效。

---

## OT-3 「只抓一级评论就够」→ 已推翻

- **曾经相信**：一级评论是观点主体；子回复接口限流风险高，追求时效时优先 `roots-only`。
- **被什么打穿**：战7 补抓 6,724 条楼中楼后，**正卷 3 条结论全部被修正**——教育应用章的实质反驳（69 条 / 1,142 赞）、被当作"高质量解析"的循环论证判定、"aleph 代表数学中的一切"的推翻，都只存在于楼中楼。
- **现在怎么做**：需要反例/纠错时**必须全量抓**；采集受限时至少对 `reply_count>=3` 的讨论楼补一轮。
- **再次推翻的条件**：
  1. 若出现一个语料，其楼中楼**全部是复读/玩梗/无实质的接龙**（例如纯粉丝控评），则"楼中楼=辩论层"应降级为"依社区类型而定"，并在 SKILL.md 明确写判据；
  2. 若某平台取消楼中楼结构（改为平铺回复流），本条需改写为"按回复深度分层"。
  3. ⚠️ 目前**所有证据都来自 B 站单一平台**（战3 + 战7），跨平台普适性未验证（见 ROADMAP P5）。

---

## OT-4 「评论真实性靠人工核对」→ 已推翻

- **曾经相信**：引用 ID 由人工核对即可，格式正确基本等于真实。
- **被什么打穿**：战4 96 条引用中揪出 1 条幻觉 ID；战6 103 条中揪出 1 条（附录索引写错一位数字）——两次都是**格式完全正确、肉眼无法分辨**的 ID。
- **现在怎么做**：强制跑 `scripts/verify_citations.py`，**差集必须为空**才允许交付。
- **再次推翻的条件**：
  1. 若出现"ID 在语料里真实存在、但被张冠李戴到错误观点上"的漏检案例 —— 说明机验只覆盖了"存在性"，没覆盖"匹配正确性"，需要升级为语义校验（这正是 P5「真·人工校验 loop」要解决的问题）；
  2. 若语料本身 ID 不唯一（上游抓取缺陷），机验会失真，需先保证输入唯一性。

---

## OT-5 「重复行只是规模虚高」→ 已推翻

- **曾经相信**：抓取结果里的重复行只会让数字偏大，不影响结论。
- **被什么打穿**：战6 实测 20,399 行中 **4,501 行（22%）是纯重复**。危害不止规模——**同一条观点被重复计入共识度**，直接污染"高赞即共识"的判断。
- **现在怎么做**：抓取端按 `rpid` 去重 + `prep.py` 输出 `dup_dropped`；交付前必查 `unique_id_count == row_count`。
- **再次推翻的条件**：
  1. 若某个上游工具保证幂等且不产生重复，本条退化为"防御性检查"，但仍应保留（成本低）；
  2. 若发现**同内容不同 ID** 的重复（同一观点被多人复读），现有 ID 去重抓不到——需要基于文本相似度去重，那是另一个量级的工程。

---

## 元观察：为什么这五次都被打穿

五次的共同点不是"我们不够仔细"，而是**都在用代理指标代替真值**：

| 我们用的代理 | 它本应代表的真值 | 失效方式 |
|---|---|---|
| 点赞数 | 群体认可度 | 被零信息量的最大公约数占据（OT-1） |
| 文本长度 | 思考深度 | 被粘贴板污染占据（OT-2） |
| 楼层深度 | 观点完整性 | 反例天然生长在深层（OT-3） |
| ID 格式正确 | 引用真实 | 幻觉 ID 格式完美（OT-4） |
| 行数 | 语料规模 | 游标重叠造成虚高（OT-5） |

**这条元观察本身也要能被推翻**：若后续出现一个"代理指标恰好等于真值"的语料形态，说明失效是语料特性而非代理指标的固有缺陷。
