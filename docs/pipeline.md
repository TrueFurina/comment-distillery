# 6 步流水线详解

```
1 接入 Ingest  →  2 预处理 Prep  →  3 通读聚类  →  4 框架抽取  →  5 结构化输出  →  6 验证
```

其中 **3、4 是 AI 的活**（不可脚本化，也不可跳过），**2、6 是脚本的活**（必须机验）。

---

## 步骤 1 · 接入 Ingest

**输入**：任意形态的群体文本。
**动作**：
- 归一成 CCF（见 `canonical-format.md`）。**只要 `id` + `text` 两列即可起步**。
- 确认规模 → 决定读取策略（见 `domains.md` 的规模表）。
- 确认语料域 → 预先知道该防哪种偏差。

**输出**：一个 CCF CSV。

**质量门槛**：`text` 列不能有一半以上是空值；`id` 唯一（重复 ID 会破坏溯源）。

---

## 步骤 2 · 预处理 Prep

```bash
python scripts/prep.py <corpus.csv> <outdir> [--low-max 8] [--low-min-len 120]
```

**产出**

| 文件 | 内容 |
|---|---|
| `all_comments.txt` | 按权重降序，每条 `[ID \| 权重N \| 层级 \| 复M]` + 正文 |
| `low_score_long.txt` | 低权重长文（真信号区），按字数降序 |
| `stats.json` | 规模 / 层级构成 / 互动 / 作者多样性 / 时间样本 / 信号词 |
| `id_map.json` | `id → 权重/层级/回复数`，**溯源依据** |

**质量门槛**：必须核对 `total_raw` 与原始行数、抽查 `top20` 是否合理（若 top1 是明显噪音，正常——那是"高权重 ≠ 高信号"的现场证据，不是 bug）。

**⚠️ 不要跳过这一步直接问 AI"帮我分析这个 CSV"**：AI 直接读原始 CSV 会丢失排序、丢掉 ID 映射（溯源就断了），也无法用两段式策略。

---

## 步骤 3 · 通读与聚类 Read & Cluster

**这是流水线的灵魂，不可外包给脚本。**

**动作**
1. **真读** `all_comments.txt`——不是统计，是逐条看内容。
2. 按主题聚类，每条标注：**共识 / 争议 / 独立观点 / 噪音**。
3. 大语料用两段式：头部通读 + `low_score_long.txt` 精筛。
4. **单独处理楼中楼/深层回复**（若语料含层级）。

**输出**：一份内部的主题地图（可写在草稿里，不用给用户）。

**质量门槛**
- 头部必须读到权重≈5–8 的位置（覆盖全部主要议题）；
- 低权重长文必须抽样精读（不是只看前几名）；
- 必须能回答："哪个议题的**反方论据**最强？"——如果答不出，说明没读够。

**常见失败**：只看 `stats.json` 的 `top_phrases` 就开始写。那得到的是词云，不是认知。

---

## 步骤 4 · 框架抽取 Synthesize

把主题地图升级为**可落手的认知结构**。三件套强制：

### 4.1 反例对冲（必做）
每写一条共识，**必须**配一条最强的反方论据。若找不到反方论据，说明：
- 该结论其实不是共识（可能只是头部声音大），或
- 你还没读到反方（回到步骤 3 找）。

> 实测价值：某次补齐楼中楼后，**4 条子回复直接推翻了基于顶层评论得出的结论**。反例对冲不是"显得客观"的装饰，是真实的纠错机制。

### 4.2 引用溯源（必做）
每条带数据的结论后附 `[源:ID|权重N|层级]`。

- ID **逐字复制**自 `id_map.json` / `all_comments.txt`，**不许凭印象补写**。
- 引用条数少而真 > 多而假。

### 4.3 盲区诚实说明（必做）
四类偏差逐一自查并披露：
- **幸存者偏差**——被议题击垮、离开的人不发言；
- **平台/人群偏差**——语料来源的受众画像（年龄/地域/职业/技术倾向）；
- **权重算法偏差**——点赞=最易被点赞的表达，不是最多人认同的立场；
- **时间切片偏差**——结论有时效，尤其涉及技术/行业/政策时。

另加一条：**处理偏差**——若未逐条读完，必须披露读了多少、用什么规则筛的。

**输出**：指南的章节骨架 + 各章内容。

---

## 步骤 5 · 结构化输出 Emit

| 档位 | 结构 | 何时用 |
|---|---|---|
| **深度版（默认）** | 多章 + 共识/争议 + 反例对冲 + 引用溯源 + 行动清单 + 精华句 + 元方法论 + 方法与边界 | 大语料、强争论、用户要"厚" |
| 标准版 | 章节 + 共识/争议梳理（省去反例/溯源细节） | 中等语料，或用户要精炼 |
| 极简版 | 10 条核心结论 + 行动清单 | 小语料（访谈/弹幕），或用户要"快看" |

**默认深度版**；仅当用户显式要求"简短/快看"时降级。**不要自作主张削弱**——用户要的常常正是那份"厚"。

**深度版的推荐骨架**（可按语料调整）：
```
0 阅读须知（校准预期 / 数据来源 / 口径）
1 事实底座（规模 / 时间 / 结构 / 语料画像）
2..N 主题分章（每章：共识 → 反例 → 溯源）
N+1 核心争议专场（吵得最凶的 1–3 个议题单独展开）
N+2 行动清单（本周 / 本月 / 长期）
N+3 精华句（元认知锚点）
N+4 元方法论（这类语料为什么值钱 / 可复用 SOP / 盲区）
附  方法与边界（诚实说明）
```

## 步骤 6 · 验证 Verify

### 6.1 引用真实性机验（⚠️ 强制，硬门）

```bash
python scripts/verify_citations.py <guide.md> <corpus.csv> [more.csv ...]
```

规则：指南中所有引用 ID 必须存在于语料 ID 全集，**差集必须为空**（退出码 0）。

**为什么必须**：LLM 写长指南时会生成"看似合理但实际不存在"的 ID——格式完全正确、肉眼无法分辨。实测战绩：**某次 96 条引用中揪出 1 条幻觉 ID**。

发现幻觉引用的处理：
1. 找到该结论对应的**真实**条目，替换 ID；
2. 若找不到，**删除该条引用**（必要时弱化该结论的表述）；
3. 重跑直到通过。

> **诚实的降级方式是减少引用条数，绝不是保留一个"看起来对"的 ID。**

### 6.2 覆盖度自查
- 头部读到了吗（权重≈5–8）？
- 低权重长文抽样了吗？
- 楼中楼处理了吗（若有）？
- 附录是否诚实披露了未读完的部分？

### 6.3 人工校验钩子（轻量）
产出末尾附一句：**"关键结论建议人工核对"**，并指明最该核对的是哪几条（通常是权重最高与最反直觉的那些）。

## 附：大语料实操参数

以 7886 条的一战为例：

| 步骤 | 参数 |
|---|---|
| 头部通读 | 读到权重≈8（约 850 条） |
| 低权重长文 | `--low-max 8 --low-min-len 120` → 筛出 486 条 |
| 精读抽样 | 486 条中取最长/最相关的 30–40 条 |
| 楼中楼 | 对 `reply_count>=25` 的子回复全量精读（206 条） |
| 覆盖 | 约 1/6 阅读量覆盖 ~95% 信号 |
| 披露 | 附录写明"未逐条读完的部分及筛选规则" |
