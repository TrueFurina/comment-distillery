## 先说我们在做什么

把一群人的自发文本（B 站评论区）炼成一份**带引用、带反例、带盲区说明**的行动指南。听起来像"评论区总结器"，区别在三个硬约束：

1. **引用机验是质量门，不是建议**：指南里每个引用 ID 都要和语料做差集，差集非空不许交付；
2. **每条共识必须配反例**；
3. **指南必须主动交代自己可能错在哪**。

七次实战下来，流水线本身没变（6 步），变的是**我们对"什么算证据"的判断标准——它被推翻了 5 次**。这条演进链才是项目真正的核心资产，下面逐条讲。

## 打穿 1：「高赞 = 高信号」

**当时相信**：按赞数降序读头部，主要观点就拿到了。

**打穿（第六战，21,100 条评论）**：这一战**8 条最具价值的评论，赞数总和只有 12**；而最高赞是一条段子，单条 **236,396**。信号和噪音差了 4 个数量级。

**现在**：头部评论只用来锚定情绪基调；真信号靠脚本筛"低权重 + 长文"专门开采。

## 打穿 2：「低赞长文 = 真信号区」

**当时相信**：打穿 1 之后，把低赞长文当金矿区。

**打穿（第七战）**：低赞区捞出来大量**粘贴板 pasta**——整段的歌词、游戏攻略、小说片段，甚至有作者自述"不小心又粘贴板了"。

**现在**：规则加人工判据——优先"有具体指称"的长文（提到具体知识点/论据/来源），跳过"无指称的叙事性长文"。

## 打穿 3：「只抓一级评论就够」

**当时相信**：`--roots-only` 抓一级评论，规模够大就行，楼中楼太慢还有限流风险。

**打穿（第七战）**：补抓 6,724 条楼中楼后，**正卷 3 处结论被修正**。反例、专业纠错、事实核查几乎**只存在于**楼中楼。

**现在**：楼中楼是必需项。采集受限时至少补 `reply_count>=3` 的讨论楼。同一战里还发现分页游标重叠造成 **22% 重复行（4,501 / 20,399）**——重复不只是规模虚高，**同一条观点被重复计入共识度，直接污染"高赞即共识"的判断**。现在抓取端按 rpid 去重、预处理端按 ID 去重、交付前必查 `unique_id_count == row_count`。

## 打穿 4：「引用真实性靠人工核对」

**当时相信**：写完自己检查一遍引用 ID 就行。

**打穿（第四战起）**：LLM 编造的幻觉 ID **格式完全正确**——前缀对、位数对、位置对，肉眼无法分辨。第四战 96 条引用里 1 条，第六战 103 条里 1 条，都是索引里错一位数字。两次都是靠脚本差集抓到的，人眼零次。

**现在**：`verify_citations.py` 是交付前强制门——提取指南全部引用 ID，与语料全集做差集，非空即打回。诚实的降级方式是减少引用条数，绝不是换一个"看起来对"的 ID。

## 打穿 5：「数据没问题，是模型不行」

这条最隐蔽。前四次被推翻后我们复盘发现一个共同模式：

> **每次失效，都是在用代理指标代替真值。**

点赞数 ↔ 认可度、文本长度 ↔ 思考深度、楼层深度 ↔ 观点完整性、ID 格式 ↔ 引用真实、行数 ↔ 语料规模。五组映射，全部在真实数据上裂开。

所以这个项目后来把重心从"更好的提示词"移到"更硬的机验"：能写进脚本卡死的判据，绝不靠自觉。

## 我们还做不到的（诚实清单）

- 机验只卡**引用存在性与格式**，不检验**结论质量**——"引用真实但推理错误"的结论能通过所有门；
- 全部实战语料来自 B 站单一平台，跨平台未验证；
- 大部分规则只有单战证据，`SKILL.md` 里明确标了 `[战N·待复现]`，复现前不进铁律区；
- golden 评估集（8 场景 / 4 类，31 个变异体验证过判分器）也只判形式与可溯源。

## 工具链（全部开源）

- **Agent 用法**：`npx skills add TrueFurina/comment-distillery`（仓库根就是技能包）
- **桌面工具**：[Release](https://github.com/TrueFurina/comment-distillery/releases/latest) 单文件 exe（11 MB，免安装，无需 Python、无需 API Key）——只做采集/预处理/导出"蒸馏包"（语料 + 方法论 + 可粘贴提示词），蒸馏交给你自己的模型
- **零依赖**：运行期纯标准库（`urllib`/`csv`/`json`），61 项测试覆盖 Python 3.10–3.13

方法论细节见仓库 `docs/retrospective.md`（七战复盘）与 `docs/overturned.md`（被推翻结论台账，每条附"什么证据会再次推翻它"）。

欢迎讨论：你们处理"引用真实但结论错误"这个层级的质量问题，用了什么办法？
